# 프로젝트 문서 안내

이 폴더는 fishing 프로젝트의 요구사항, 설계, 개발 계획을 보관합니다.
대화에서 결정한 내용을 프로젝트 파일로 남겨 다음 개발 작업에서도 확인할 수 있게 합니다.

## 문서 목록

| 문서 | 기록하는 내용 | 갱신하는 시점 |
| --- | --- | --- |
| [요구사항](requirements.md) | 제품 목적, 요구사항, 미결정 사항 | 기능이나 범위를 결정할 때 |
| [프로젝트 환경 및 버전](environment.md) | 개발 환경, 도구·패키지 버전, 검증 범위 | 환경 점검, 앱 초기화, 버전 변경 시 |
| [기술 설계 및 결정 기록](architecture.md) | 기술 구성, 결정 이유와 영향 | 기술이나 구조를 결정·변경할 때 |
| [개발 계획](plan.md) | 작업 순서, 상태, 완료 기준 | 작업을 시작하거나 완료할 때 |
| [채팅 내용](채팅%20내용.md) | 대화의 핵심, 결정 배경, 다른 환경에서 이어가는 방법 | 대화 기록을 남기거나 작업 환경을 이전할 때 |

## 작성 원칙

- 현재 합의된 내용을 본문에 유지합니다. 대화 전체를 복사하지 않습니다.
- `채팅 내용.md`는 과거 대화를 정리한 기록입니다. 현재 요구사항과 기술 상태는 각 명세 문서에서 관리합니다.
- 제안과 확정 사항을 구분합니다. 답변이 없는 항목은 미정으로 둡니다.
- 요구사항에는 고유 ID를 붙여 설계, 구현, 검증에서 참조합니다.
- 요구사항의 `확정`은 만들기로 합의했다는 뜻이며, 구현 완료를 뜻하지 않습니다.
- 화면과 데이터 구조가 구체화되면 별도 문서를 추가하고 이 목록에 연결합니다.
- 중요한 결정은 이유와 날짜를 남기고, 변경 시 기존 기록을 대체하는 결정을 덧붙입니다.
- 비밀번호, 토큰, 실제 사용자의 개인정보는 문서에 넣지 않습니다.

## 작업 흐름

1. 요구사항과 완료 기준을 구체화합니다.
2. 필요한 화면·데이터·기술 설계를 작성합니다.
3. 개발 계획에서 구현할 작업을 정합니다.
4. 구현하고 완료 기준에 맞게 검증합니다.
5. 결과와 변경된 결정을 문서에 반영합니다.

다음 작업을 시작할 때 이 문서와 관련 요구사항·설계·개발 계획을 함께 확인합니다.
