## 7. VS Code만으로 개발할 수 있는지

사용자 질문:

> 리액트네이티브 하는거면 vscode 만으로는 부족해?

답변 요지:

- 코드 작성은 VS Code에서 진행할 수 있습니다.
- 실행과 빌드를 위해 Node.js·npm 및 대상 플랫폼에 맞는 도구가 필요합니다.
- Android Studio는 Android SDK·에뮬레이터와 로컬 빌드 환경 관리에 사용합니다.
- Expo Go는 간단한 실행 확인과 학습에 사용할 수 있습니다.
- 정식 앱 개발과 기능 검증에는 앱 전용 개발용 빌드를 사용하는 방향을 권했습니다.
- EAS Build를 선택하면 클라우드에서 설치 파일을 만들 수 있습니다.

개발용 빌드와 EAS 사용은 안내한 개발 방식이며, 아직 관련 패키지를 설치하거나
빌드 설정을 적용하지 않았습니다.

## 8. iOS 개발에 Mac이 필수인지

사용자 질문:

> ios는?

이어진 질문:

> 리액트네이티브로 개발하는게 mac가 꼭 필요하지?

답변 요지:

| 작업 | 안내한 개발 환경 |
| --- | --- |
| Android 개발·실행·빌드 | Windows에서도 가능 |
| iOS 공통 앱 코드 작성 | Windows에서도 가능 |
| EAS로 iOS 클라우드 빌드 | 개인 Mac 없이 가능 |
| EAS 개발용 빌드를 실제 iPhone에 설치 | Apple 개발자 유료 계정 등 관련 준비 필요 |
| 내 컴퓨터에서 iOS 시뮬레이터 실행·직접 빌드 | Mac + Xcode 필요 |

Windows + EAS + 실제 iPhone으로 iOS 개발과 테스트를 이어갈 수 있다고 설명했습니다.
iOS 네이티브 디버깅과 로컬 시뮬레이터 사용에는 Mac이 유리합니다.

## 9. React Native와 Expo를 사용하는 시점

사용자 질문:

> 안드로이드, ios 를 포함해서 리액트네이티브 로 개발을 하고 나중에 expo를 사용한다?

답변 요지:

처음부터 React Native + Expo를 함께 사용해 프로젝트를 구성하는 계획입니다.
Expo를 마지막에 추가하는 순서가 아닙니다.

- React Native: Android·iOS 화면과 기능을 만드는 기반
- Expo: 프로젝트 생성, 네이티브 기능 연결, 개발·빌드를 지원하는 프레임워크
- Expo Go: 간단한 실행 확인에 사용하는 별도 앱
- 개발용 빌드: 우리 앱에 필요한 네이티브 기능과 설정을 포함한 개발·테스트용 앱
- EAS Build: 필요할 때 사용하는 클라우드 빌드 서비스

예상 흐름은 프로젝트 생성 → 기능 구현 및 두 플랫폼 테스트 → 출시용 빌드 → 스토어 제출입니다.

공식 OpenAI 문서와 현재 채팅 정보를 확인해 안내했습니다.

- 대화 동기화와 로컬 프로젝트 파일 이동은 별개입니다.
- 맥북에서 직접 개발하려면 저장소와 문서를 맥북으로 가져오고 해당 폴더를 연결합니다.

계정·워크스페이스와 앱의 지원 기능에 따라 채팅 접근 방법은 달라질 수 있습니다.

## 14. 맥북에서 이어가는 방법

Git push가 완료된 뒤 맥북 터미널에서 저장소를 받습니다.

```sh
git clone https://github.com/pork1375-png/fishing.git
cd fishing
```

비공개 저장소라면 해당 저장소에 접근 가능한 GitHub 인증이 필요합니다.
이미 복제한 저장소가 있다면 로컬 변경 상태를 확인하고 최신 내용을 가져옵니다.
그다음 Codex에 맥북의 `fishing` 폴더를 연결합니다.

새 채팅에서는 다음과 같이 요청하면 됩니다.

> docs/README.md와 docs/채팅 내용.md를 먼저 읽고 fishing 프로젝트를 이어서 진행해줘.
> React Native + Expo 기반 출조노트 앱이며 Android와 iOS 출시가 목표야.
> 현재는 문서만 준비되어 있으니 맥북 개발 환경을 확인하고 문서를 갱신한 뒤,
> 요구사항과 첫 버전 범위를 함께 구체화해줘.

현재는 `package.json`이 없으므로 저장소를 받은 직후 `npm install`이나 앱 실행을
진행할 수 있는 단계가 아닙니다. 먼저 요구사항과 초기화 구성을 정해야 합니다.
